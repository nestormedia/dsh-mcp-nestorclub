# dsh-mcp-nestorclub

Плагин для DeepSeek Harness: подключает MCP-сервер `nestorclub-mcp`
(`https://mcp.nestorclub.com`), и инструменты сервера появляются у агента как
`mcp__web__*` — `list_sites`, `get_page`, `write_page`, `search_pages` и
остальные.

Ключ доступа плагин **спрашивает сам**: после установки на его странице в
разделе **Plugins** появляется карточка с полем ввода, а задать ключ можно и
командой `/mcp-key` прямо в чате. Руками в `cordis.patch.yml` ничего писать не
нужно — плагин сохраняет ключ туда сам.

## Что нужно

- DeepSeek Harness `0.2.2-rc.1` или новее;
- ключ `x-api-key` сервера nestorclub;
- сетевой доступ к `https://mcp.nestorclub.com`.

## Установка

1. **Plugins → Add plugin**.
2. Адрес репозитория:

   ```
   https://gitea.xn--txe.net/nestor/dsh-mcp-nestorclub.git
   ```

   Суффикс `.git` обязателен — без него pnpm пытается скачать архив и падает.
3. **Install**, затем перезапустите приложение (клиентская половина грузится
   вместе со страницей, поэтому после установки нужен один refresh).

Если в профиле осталась вставленная руками строка `mcp-nestorclub` (старый
способ), удалите её: два клиента с одним `serverName: web` конфликтуют.

## Ключ доступа

Ключа в репозитории нет — он принадлежит тому, кто пользуется плагином.

**Через интерфейс.** Plugins → «MCP: nestorclub» → карточка «MCP: nestorclub» →
вставьте ключ в поле → **Сохранить**. Кнопка **Проверить ключ** проверяет уже
сохранённый ключ.

**Через чат.** `/mcp-key nc-…` — сохранить; `/mcp-key` без аргумента — статус.

Что происходит при сохранении: плагин отправляет `initialize` на сервер с этим
ключом, и только если сервер ответил, пишет профильный override:

```yaml
- id: mcp-nestorclub
  name: '@deepseek-ai/dsh-mcp-client'
  config:
    serverName: web
    transport: streamable-http
    url: https://mcp.nestorclub.com
    headers:
      x-api-key: 'nc-…'
    failOnStartupError: false
```

Дальше `dsh-mcp-client` перезагружает соединение на месте. Профиль можно править
и руками — плагин читает ключ оттуда же, — но тогда проверка перед сохранением
не выполняется.

Без ключа Harness работает как обычно: строка MCP подключиться не может,
инструментов `mcp__web__*` нет, а карточка плагина показывает «ключ не задан».

## Проверка

- **Plugins** → у плагина «MCP: nestorclub» статус «ключ задан»;
- **Проверить ключ** → «Ключ рабочий: сервер ответил»;
- в новом чате агент видит `mcp__web__*`; например, «покажи список сайтов»
  вызывает `mcp__web__list_sites`.

Ручная проверка сервера без Harness:

```
curl -sS https://mcp.nestorclub.com \
  -H 'content-type: application/json' \
  -H 'accept: application/json, text/event-stream' \
  -H 'x-api-key: ВАШ_КЛЮЧ' \
  -d '{"jsonrpc":"2.0","id":1,"method":"initialize","params":{"protocolVersion":"2026-07-28","capabilities":{},"clientInfo":{"name":"curl","version":"1"}}}'
```

Ответ с `"serverInfo":{"name":"nestorclub-mcp"}` — ключ и сервер в порядке.

## Как это устроено

Патч плагина вставляет две строки:

| Строка | Что это |
|---|---|
| `mcp-nestorclub` | штатный `@deepseek-ai/dsh-mcp-client` с транспортом Streamable HTTP |
| `mcp-nestorclub-host` | сам пакет `dsh-mcp-nestorclub`: Host-половина с API и командой |

Host-половина (`lib/index.js`) даёт `/mcp-nestorclub/status`, `/key`, `/check` и
команду `/mcp-key`. Клиентская половина (`lib/client.js`) регистрируется в слот
`plugins.bundle.config` страницы Plugins под ключом `dsh-mcp-nestorclub` — так
карточка попадает на страницу именно этого плагина.

Сохранение ключа идёт через службу `configEditor`: она проверяет весь конфиг
строки по схеме `dsh-mcp-client`, пишет override атомарно и перезагружает
компоновку. Плагин не переписывает файл профиля сам.

## Обновление и удаление

- **Обновление:** Plugins → Remove, затем Add plugin заново: git-зависимости не
  попадают в список версий реестра, кнопки Update у них нет.
- **Удаление:** Plugins → Remove; затем уберите override с ключом из
  `cordis.patch.yml`, если он больше не нужен.

## Ограничения

- Нужен рабочий ключ: без него инструментов нет, и это видно в карточке плагина.
- Ключ лежит в файле профиля открытым текстом. Это ваш файл, он не в git; при
  передаче профиля другому человеку ключ передаётся вместе с ним.
- Проверка ключа — один запрос `initialize` с таймаутом 15 с; сервер, который
  отвечает, но потом отдаёт пустой `tools/list`, пройдёт проверку.
- Инструменты появляются в сессиях, созданных после переподключения; уже
  открытый чат новый набор инструментов не подхватывает.
